# Модуль онлайн-платформы математического анализа спектральных данных

## Назначение

Проект представляет собой FastAPI-веб-приложение для загрузки, проверки, предобработки, визуализации и математического анализа спектральных данных. Модуль `/analysis` помогает привести спектры к единому датасету, обучить модели классификации, кластеризации или регрессии, сохранить результаты и повторно использовать обученные модели.

## Возможности

- импорт спектральных данных из Excel, CSV, TXT/ESP и ZIP с наборами спектров;
- загрузка правильного датасета CSV/XLSX в формате «одна строка = один спектр»;
- предобработка: baseline correction, smoothing, normalization, crop;
- визуализация исходных и обработанных спектров;
- классификация: PLS-DA, SVM, Random Forest, Decision Tree;
- кластеризация: k-means, HCA;
- регрессия: PLS Regression, SVR;
- сравнение методов с таблицей метрик;
- сохранение моделей и metadata;
- история экспериментов текущего пользователя;
- экспорт CSV, XLSX, JSON и ZIP-пакетов.

## Структура проекта

- `routes/` - FastAPI routes, включая `/analysis`;
- `services/` - бизнес-логика: импорт датасетов, модели, сохранение запусков;
- `templates/` - HTML-шаблоны страниц;
- `static/` - CSS и JavaScript интерфейса;
- `datasets/` - локальные runtime-датасеты, не коммитятся;
- `saved_models/` - сохранённые модели, не коммитятся;
- `saved_runs/` - история запусков, не коммитится;
- `uploads/` - временные пользовательские загрузки, не коммитятся;
- `user_data/` - пользовательские датасеты, модели и runs при авторизации, не коммитятся.

## Установка

Windows:

```bash
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Запуск

```bash
uvicorn app:app --reload
```

Примечание: сообщения `watchfiles` при запуске с `--reload` не являются ошибкой. Это режим авто-перезапуска uvicorn при изменении файлов. Для более спокойного запуска без этих логов используйте:

```bash
uvicorn app:app
```

После запуска:

- главная страница: `http://127.0.0.1:8000/`;
- модуль анализа: `http://127.0.0.1:8000/analysis`.

## Переменные окружения

Скопируйте `.env.example` в `.env` и задайте локальные значения:

- `SESSION_SECRET_KEY` - секрет сессий;
- `DATABASE_URL` - внешняя БД, если используется;
- `USER_DB_PATH` - путь к локальной SQLite БД пользователей;
- `OPENROUTER_API_KEY` - ключ для AI-анализа, если используется;
- `UPLOAD_DIR`, `DATASETS_DIR`, `SAVED_MODELS_DIR`, `SAVED_RUNS_DIR`, `USER_DATA_DIR` - runtime-каталоги.

Реальные `.env`, пользовательские датасеты, модели и история запусков не должны попадать в git.

## Формат правильного датасета

Правильный датасет содержит один спектр в каждой строке. Первые колонки являются metadata, далее идут спектральные признаки с числовыми заголовками:

```text
sample_id,target,source_sheet,source_file,473.50,474.10,474.70
sample_1,control,Sheet1,file.xlsx,10.2,11.0,10.7
sample_2,test,Sheet1,file.xlsx,15.1,14.8,15.4
```

Для регрессии `target` может быть числовым, например концентрацией. Для классификации `target` должен быть категориальным.

## Ограничения

- WDF/SPC не реализованы как полноценные бинарные форматы; нужны отдельные парсеры приборных файлов.
- Качество моделей зависит от числа образцов, качества спектров и корректности target.
- Для применения сохранённой модели новая матрица признаков должна совпадать с обучающей спектральной сеткой.
- Малые датасеты дают нестабильные метрики; используйте кросс-валидацию и независимую проверку.
- AI-анализ работает только при наличии `OPENROUTER_API_KEY`.
- Загрузка внешних `.joblib` моделей допустима только в доверенной локальной среде.

## Использование

1. Откройте `/analysis`.
2. Выберите режим работы.
3. Загрузите датасет или правильный CSV/XLSX.
4. Проверьте summary и график спектров.
5. При необходимости примените предобработку и сохраните processed-версию.
6. Выберите цель анализа и метод.
7. Запустите анализ.
8. Изучите вкладки «Сводка», «Метрики», «Графики», «Скачать».
9. Откройте историю экспериментов или сохранённые модели для повторной работы.

## Проверка перед публикацией

Перед сохранением изменений в GitHub рекомендуется выполнить:

```bash
python -m compileall .
python scripts/smoke_test_importers.py --excel data/Raman_krov_SSZ-zdorovye.xlsx --zip data/Raman_slit_dependence_16_03_2026.zip
uvicorn app:app --reload
```

На странице `http://127.0.0.1:8000/analysis` проверьте:

- импорт Excel с листами-классами и ZIP/ASC без автоматического target;
- предпросмотр графика датасета;
- предобработку raw/processed;
- обучение PCA, k-means и PLS-DA;
- сохранение модели и применение сохранённой модели к новому спектру;
- отображение результата во вкладках «Сводка», «Метрики», «Графики», «Скачать», «JSON».

В репозиторий не следует добавлять `.env`, пользовательские загрузки, runtime-датасеты, сохранённые модели, историю запусков, результаты экспериментов, `.joblib` и `.pkl` файлы.
